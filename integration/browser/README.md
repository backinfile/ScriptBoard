# Chromium browser gate

This directory contains ScriptBoard's deterministic end-to-end browser regression gate. The runner builds a local fixture, starts the real server-rendered application on an ephemeral loopback port, exercises it in Chromium, and refreshes the reference screenshots in [`snapshots/`](./snapshots/).

The suite is test-only. It does not add Node.js, Playwright, or a browser runtime to production builds.

## Prerequisites

- Go 1.26
- Node.js and pnpm
- Chromium installed through Playwright

## Run the gate

From the repository root:

```powershell
cd integration/browser
pnpm install
pnpm exec playwright install chromium
pnpm test
```

`pnpm test` performs the following steps:

1. removes and recreates `test-results/`;
2. builds [`fixture/main.go`](./fixture/main.go);
3. starts the fixture and waits for its loopback URL;
4. launches Chromium at the fixed desktop viewport;
5. runs the interaction and layout assertions;
6. writes current screenshots to [`snapshots/`](./snapshots/);
7. stops the fixture and browser, including after a failure.

The command exits non-zero on an assertion, browser console error, page error, or fixture failure.

## Coverage

The gate checks:

- sign-in, localization, grouped navigation, direct routes, and enhanced task panels;
- host-filesystem browsing, search, upload, conflict handling, previews, editing, and Trash;
- real script execution, live output, run history, filtering, and actor presentation;
- Quick Run creation, grouping, editing, copying, ordering, and soft locks;
- schedules and variable-value controls;
- Host Status, application observation, website monitoring, and status JSON;
- Docker and host-file live logs, including paging, pause/resume, copy, clear, and severity;
- keyboard dismissal, console cleanliness, table alignment, and horizontal overflow;
- desktop `1440 × 1000` and targeted mobile `390 × 844` layouts;
- selected workflows without JavaScript.

Modern non-Chromium browsers remain best-effort compatibility targets; they are not part of this automated gate.

## Artifacts

| Path | Purpose | Tracked |
| --- | --- | --- |
| `snapshots/*.png` | Visual regression references and README images | Yes |
| `test-results/` | Temporary fixture binary and run artifacts | No |
| `node_modules/` | Local test dependencies | No |

Every successful or failed run may rewrite tracked screenshots. Review image diffs before committing them. Curated README images live under `docs/images/readme/` and are not generated by the current runner.

## Maintaining the suite

- Keep test data deterministic and local; do not depend on external services.
- Prefer user-visible assertions over implementation details.
- Add desktop overflow checks for new table or workspace layouts.
- Add a focused mobile check when a workflow changes shape at narrow widths.
- Treat console errors as failures.
- Keep dependencies inside this directory so the production Go build stays self-contained.
