# ScriptBoard MVP 验收标准

本文是冻结需求的可验证交付标准。除明确标注平台特有的条目外，Windows 与 Linux 均需通过。

## 1. 认证与安全

- [ ] 首次启动自动创建唯一系统管理员和随机初始密码；不强制首次登录修改。
- [ ] 系统管理员可创建、改名、停用、恢复、改角色和重置普通用户密码，但不能创建第二个管理员、停用或降级自己。
- [ ] 维护员拥有除用户管理外的全部能力；执行员可读文件并执行脚本和快捷项；观察员只能查看运营页面且不能访问文件页。
- [ ] 密码重置、角色变更和停用立即撤销目标用户全部 Session 与活动 SSE/日志连接。
- [ ] Run 保存启动用户 ID 和用户名快照；执行员只能停止自己启动的 Run。
- [ ] 审计保存操作者 ID、用户名与角色快照，且随机密码只在创建或重置成功响应中展示一次。
- [ ] Argon2id 哈希包含版本化参数和独立 Salt，数据库不出现明文密码。
- [ ] 密码不满足 12 Unicode 字符、超过 256 UTF-8 字节或等于用户名时被拒绝。
- [ ] 未登录访问文件、下载、日志、SSE、变量、计划和执行路由均被拒绝。
- [ ] 所有状态修改路由拒绝缺失或错误 CSRF Token。
- [ ] Session 空闲 12 小时、绝对 7 天后失效；服务重启不使有效 Session 失效。
- [ ] 修改用户名/密码撤销全部 Session；退出只撤销当前 Session。
- [ ] 登录失败 5 次后出现指数退避，且不存在永久锁死。
- [ ] 明文 HTTP 配置非回环监听时服务拒绝启动。
- [ ] HTTPS 非回环模式设置 Secure Cookie；可信代理之外的转发 IP 头被忽略。
- [ ] 服务日志、Run 错误和审计中不出现密码、Cookie、CSRF、变量值或完整环境。

## 2. 主机文件边界

- [ ] Windows 顶层枚举可用本地、移动和网络卷；Linux 顶层进入 `/`，面包屑、搜索、表单和文件路由完整处理绝对路径、Unicode、Windows 盘符及平台大小写。
- [ ] State Root、Install Root、活动配置、管理员密码文件、TLS 私钥和各文件系统回收区在列表中隐藏，直接 URL 访问也拒绝。
- [ ] 受保护路径自身与后代不可访问；对包含它的祖先执行编辑、移动、删除、覆盖或执行同样拒绝，编码和大小写变化不能绕过。
- [ ] 符号链接、Junction、Reparse Point 和特殊文件可见但受限且不跟随；真实磁盘、普通挂载、网络挂载和临时文件系统可进入。
- [ ] Linux `/proc`、`/sys`、`/dev` 等内核虚拟文件系统只显示受限入口；卷离线、权限拒绝和卷根不可移动/删除均返回可解释错误。
- [ ] 隐藏文件默认不显示，Windows Hidden/System 属性均生效；浏览器快捷访问保存版本化绝对路径，失效或受保护项只能移除。
- [ ] 管理员/维护员可写，执行员只读且可执行，观察员无文件页权限；执行员能够读取服务身份可读普通主机文件这一边界有明确测试。

## 3. 上传、编辑、下载与文件系统回收区

- [ ] 多文件上传逐文件返回结果；目录上传、链接和特殊文件被拒绝；上传中断不在目标路径留下半文件。
- [ ] 同名上传默认拒绝；确认替换后旧文件进入目标文件系统回收区且新文件原子可见。
- [ ] 只有不超过 1 MiB、有效 UTF-8 且无 NUL 的普通文件可在线编辑；外部改动触发摘要冲突且不覆盖。
- [ ] 运行中脚本和被文件操作租约覆盖的路径不能编辑、替换、移动或删除，相关祖先路径同样受保护。
- [ ] 栅格图片按允许类型安全预览；SVG/HTML/PDF/Office/未知格式不内嵌；单文件下载支持 Range，目录不生成 ZIP。
- [ ] 删除只进入源文件系统中带实例所有权标记的私有回收区；无法安全建立回收区时拒绝且不永久删除。
- [ ] 回收条目保存原绝对路径；冲突路径默认不能恢复，永久清理要求明确确认。
- [ ] 删除被引用脚本会禁用计划并使快捷项失效；恢复不自动重启计划。
- [ ] Linux 可切换 `u+x` 且不改变 group/other 位；Windows 不显示该操作。

## 4. 移动、持久化操作与恢复

- [ ] 同文件系统移动使用原子重命名，并在事务中更新快捷执行和计划绝对路径；Run 历史路径不改写。
- [ ] 可注入卷拓扑覆盖跨文件系统成功、空间不足、校验失败、受限子项、同名冲突和取消；源、目标、临时项与回收项始终处于可解释状态。
- [ ] 跨文件系统预扫描在复制前拒绝链接、特殊文件和无法无损保留元数据的目录，并按实际目标文件系统检查空间。
- [ ] 复制保留并校验内容、时间、权限及平台元数据，通过目标同目录临时项和原子提交避免暴露半成品。
- [ ] 目标提交前失败或取消会清理临时项并保持源不变；目标提交后继续将源移入源文件系统回收区并事务更新引用。
- [ ] 在每个持久化阶段模拟崩溃，重启后均能自动继续或回滚；状态端点和 SSE 展示扫描、字节进度、提交、完成与失败。
- [ ] 路径租约阻止活动 Run 与文件操作以及两个重叠文件操作互相竞争。
- [ ] 内置 Git 版本保护的设置、路由、Run 检查点、数据库状态和配置均不存在；磁盘已有 `.git` 与历史不被修改或删除。

## 5. 脚本与参数

- [ ] 支持的扩展名无需注册即可在原位置执行，工作目录为脚本父目录。
- [ ] Linux 和 Windows 默认执行器链按 PRD 顺序解析，可通过 YAML 指定绝对路径。
- [ ] 执行器不可用时回退；脚本一旦启动，非零退出不回退重跑。
- [ ] Windows Terminal 不参与执行器链；托盘入口不会影响服务日志捕获。
- [ ] shellwords 能正确处理空格、单双引号和反斜杠，不执行管道、重定向或命令替换。
- [ ] `{{NAME}}` 仅独占参数时解析；不存在变量、嵌入引用或非法名称被拒绝。
- [ ] 参数 16 KiB、变量值 4 KiB、256 参数、1,000 变量上限生效。
- [ ] Run 同时保存参数模板与当时实际参数数组。
- [ ] 脚本继承服务身份和环境，历史记录实际身份、执行器、路径和 SHA-256。

## 6. 并发、停止与状态

- [ ] 不存在队列或全局并发上限；不同脚本可立即并发。
- [ ] 人工重复启动同一文件 ID 时二次确认；确认后可并发。
- [ ] 执行状态只按冻结状态机迁移，终态不可逆。
- [ ] 第一次停止进入 stopping 并请求优雅退出；第二次停止强杀完整进程树。
- [ ] 默认无超时；指定超时后进入 timing_out，30 秒宽限后自动强杀。
- [ ] Linux 子进程组与 Windows Job Object 的子孙进程均被停止。
- [ ] 正常停服停止新工作、取消全部 Run，并在 30 秒后强杀残留。
- [ ] 异常服务退出尽量连带终止进程树；重启后旧活动 Run 变为 disconnected。
- [ ] Run 元数据没有网页删除入口，也不存在批量清空接口。

## 7. 日志与 SSE

- [ ] stdout/stderr 进入同一有序事件流，并保留来源标记。
- [ ] 页面刷新后使用 Last-Event-ID 继续，既不重放全部日志也不静默丢失可用事件。
- [ ] 不解析 ANSI、不提供 stdin 或 PTY；控制字符安全转义。
- [ ] 无效 UTF-8 不破坏页面，并显示编码错误标记。
- [ ] 达到 100 MiB 后保留 5 MiB 头部和约 95 MiB 尾部，显示截断及丢弃量。
- [ ] 日志达到上限后进程不会因 stdout/stderr 管道阻塞。
- [ ] 页面初始与 DOM 事件上限生效，暂停显示不暂停后台日志读取。
- [ ] 90 天或全局 1 GiB 触发日志清理时，Run 元数据保留并标记 log_expired。
- [ ] 日志写入失败时 Run 标记 log_incomplete，脚本不会被自动终止。
- [ ] 当前 Docker 应用与已 Pin 停止容器都有日志入口；宿主应用被明确拒绝，Engine 或日志驱动不可读时不使用其他来源回退。
- [ ] 普通主机文本文件可从列表和预览持续查看；追加、快速截断、重命名轮转、删除等待与重建恢复均不漏读可证明连续的内容。
- [ ] Docker multiplex 顺序及 stdout/stderr 来源、TTY combined 来源和独立时间戳正确；历史与实时续传使用同一版本化源游标并去重。
- [ ] 源日志首次最多 500 行，向上分页最多 500 行或 1 MiB；单行最多 256 KiB，超长行、CRLF、无末尾换行、无效 UTF-8 与控制字符安全处理。
- [ ] `error/fatal/panic` 和 `warn/warning` 按不区分大小写的任意位置匹配，Error 优先；普通 stderr 不会仅因来源被标为 Error。
- [ ] Error/Warning 行使用整行背景、左轨和文本级别共同区分，深色画布对比度足够，桌面与移动端没有水平溢出。
- [ ] 源日志暂停会关闭 SSE，继续从游标恢复；自动跟随、新增行计数、顶部加载锚点、清屏与复制均可用。
- [ ] 浏览器源日志工作集限制为 20,000 行或 16 MiB；服务端限制为 8 路 SSE、4 路历史读取，超限返回 429，SSE 每 15 秒心跳。
- [ ] Docker/文件日志页面、JSON 与 SSE 均要求 Session、设置 `no-store`，正文仅通过 `textContent` 渲染，且不进入数据库、审计或服务诊断日志。

## 8. 快捷执行与计划

- [ ] 快捷项只能由维护员从主机脚本文件或历史 Run 主动保存，可命名、排序和删除；从文件保存时不创建 Run。
- [ ] 快捷项可编辑名称、参数和超时但不能借此改写脚本路径；复制项拥有新 ID、默认未锁定，并在同分组中紧随来源项。
- [ ] 快捷执行分组可创建、重命名、排序和删除；快捷项至多属于一个分组，可在分组间移动，删除非空分组后条目按原顺序保留在“未分组”。
- [ ] 分组折叠状态按浏览器本地记忆、默认展开，禁用 JavaScript 时内容仍可访问；移动端不依赖悬停即可完成全部操作。
- [ ] 软锁持久化并同时约束界面和服务端：锁定项不能编辑或删除，但仍可启动、复制、移动分组、排序并接受系统路径引用更新。
- [ ] 正常快捷项单击即 POST 启动；同脚本运行时显示确认；失效路径不能启动。
- [ ] 计划分组可创建、重命名、排序和删除；新建或编辑计划只能选择已有分组或“未分组”，删除非空分组后计划保留在“未分组”。
- [ ] 计划名称、可空分组引用、脚本参数、超时与重叠策略可在创建和编辑流程中保存并回显。
- [ ] 五段 cron 校验、常用规则与表达式双向同步、未来五次预览使用实例统一时区；无法映射的有效表达式保留为自定义 Cron。
- [ ] 服务停机期间不补执行，重启后从下一未来时间继续并记录错过汇总。
- [ ] 默认允许计划重叠；禁止重叠时只记录 skipped 触发，不创建 Run。
- [ ] 计划触发使用与手动执行相同的变量、主机路径保护、执行器、日志和状态模型。
- [ ] 未创建 Run 的触发明细一年后聚合，管理员不能删除。
- [ ] 不读取或修改系统 crontab。

## 9. 审计与历史

- [ ] 认证、文件、持久化文件操作、Run、计划、变量、快捷项和自动清理均产生审计事件。
- [ ] 审计事件包含时间、动作、目标、结果与来源地址，但不含敏感值或文件内容。
- [ ] 审计页面不能修改单条事件，默认保留一年并可下载。
- [ ] Run 历史永久不可删除；计划和快捷来源删除后仍有名称快照可解释。

## 10. 服务、托盘与配置

- [ ] Windows 服务默认 LocalSystem、自动启动；Linux systemd 服务默认 root、自动启动。
- [ ] 手动运行时继承当前用户且不因不是最高权限而拒绝启动。
- [ ] 服务安装、卸载、启停、状态、admin reset、config validate、doctor、version 命令可用。
- [ ] 卸载服务不删除配置、主机文件、数据库或磁盘上已有 Git 历史。
- [ ] 不存在用户 backup/restore 命令；`update status|check|recover` 命令可用且恢复命令要求完整 Operation ID 二次确认。
- [ ] Windows 托盘无主窗口、单实例，菜单与 PRD 一致；退出托盘不停止服务。
- [ ] 托盘区分服务进程运行与 HTTP 就绪；端口错误时显示异常并可打开日志。
- [ ] 默认配置优先级正确，命令行覆盖不写回 YAML。
- [ ] 同一状态目录第二个服务实例被排他锁拒绝。

## 11. SQLite、磁盘与升级

- [ ] SQLite 运行时 WAL、FULL synchronous、foreign keys 与 busy timeout 生效。
- [ ] Run 输出不逐事件写入 SQLite。
- [ ] 全新 State Root 创建 schema 21；schema 20 在单事务内只增加 Assistant 表并升级到 21，原用户与业务数据保持不变；早于 20 或高于当前版本的数据库在写入前明确拒绝。
- [ ] 带 `managed_root`、`git_executable` 的旧 YAML、环境变量和命令行参数明确拒绝；旧浏览器固定项不迁移。
- [ ] 状态卷低于 100 MiB 拒绝新执行；任一实际目标文件系统低于 100 MiB 时拒绝对应写操作。
- [ ] `doctor` 只读检查配置、受保护路径、SQLite、日志、执行器、端口、TLS、服务和关键磁盘，不泄漏敏感值。

## 12. 发布与兼容

- [ ] Windows amd64/arm64 ZIP 含服务、托盘、托盘启动器和 updater；Linux amd64/arm64 tar.gz 含服务和 updater。
- [ ] 正式 Tag Release 生成四个平台归档、`SHA256SUMS`、归档内 `RELEASE.json`、严格发布清单及其 Ed25519 detached signature；缺少签名 Secret 时发布失败。
- [ ] `version --json`、Git Tag、清单、归档名和 `RELEASE.json` 的版本、Commit、平台及协议一致；不依赖 Node.js、Redis、消息队列或外部运行时。
- [ ] 新版服务安装采用版本化 Install Root；Linux 使用稳定 `current` 入口，Windows 服务明确指向当前 Installed Release；同名旧式服务、缺失新版安装元数据或从不完整发布包安装时明确拒绝，不执行猜测、迁移或清理。
- [ ] 正式构建默认按配置周期检查固定官方仓库的最新非 Draft、非 Prerelease 稳定版；开发构建不联网，便携构建不可应用更新。
- [ ] 未签名、未知 key ID、签名错误、Tag/版本/仓库不一致、平台不匹配、摘要错误、协议过新、超限或含路径穿越/链接/重复条目的归档全部拒绝。
- [ ] 更新只能由已登录管理员通过 CSRF 保护的动作发起；安装前有明确二次确认，不提供无人值守安装。
- [ ] 进入维护门后调度暂停且新 Run 被同步拒绝；存在任何活动 Run 时返回冲突、恢复正常入口且不停止 Run。
- [ ] updater 在主进程退出后保存数据库快照、切换目标版本并启动 Validation Mode；验证期间不触发计划、不接受 Run 或业务写请求。
- [ ] 目标服务只有在服务状态、精确版本运行标记与 HTTP 就绪持续通过后才提交；启动、迁移或验活失败自动恢复旧版本和数据库。
- [ ] Update Operation 每个重要阶段持久化；中断后能继续、回滚或进入带 Operation ID 的明确人工恢复状态，最终结果只导入审计一次。
- [ ] Web 更新页显示构建、安装形态、检查错误、发布说明、验证/准备状态、活动 Run 和跨重启结果；断线期间自动等待服务恢复。
- [ ] Windows 10/11、Server 2019+ 与至少两个代表性 systemd Linux 发行版通过服务生命周期测试。
- [ ] 桌面 Chromium 自动化覆盖登录、分组导航、任务面板、运行详情和关键视觉快照。
- [ ] Chrome、Edge、Firefox、Safari 保持最佳努力兼容；它们不作为每次提交的自动化门禁。
- [ ] 移动端可登录、导航、浏览文件、启动、看日志、快捷执行、停止和配置计划，且不依赖桌面悬停操作。
- [ ] Web 的导航、状态、动作、错误和日期在简体中文与美式英语下完整本地化；首次访问按 `Accept-Language` 选择，Cookie 可覆盖并持久化选择。
- [ ] 托盘和 CLI 帮助为简体中文；结构化标识与展开后的技术详情保持英文。

## 13. 明确不验收

MVP 不验收自定义 RBAC、沙箱、公共 API、DAG、多服务器、Docker 正式部署、系统 crontab、内置 Git 版本保护、用户备份命令、通知、插件、交互终端、目录打包、通用权限编辑、用户 impersonation、无人值守自动安装、自定义更新源/频道、旧配置/状态迁移、Web 之外界面的多语言或正式多实例。

## 14. 宿主概览

- 登录、已登录访问 `/login`、根路径和品牌入口最终进入 `/monitor`；未登录仍只能进入登录页。
- 概览在两个采样周期内显示 CPU、内存、存储、磁盘 I/O、网络和 ScriptBoard 进程的可用指标，并显示最近五条活动 Run。
- 15 分钟视图使用五秒实时样本；1 小时、6 小时和 24 小时视图使用跨重启保留的分钟平均值与峰值。
- `/monitor/data` 与 `/monitor/status` 只允许有效 Session，拒绝未知时间范围并设置 `Cache-Control: no-store`。
- 单类采集失败、设备消失、历史写入失败或服务重启形成明确错误或图表缺口，不能伪造零值，也不能影响核心功能。

## 16. 网站监控

- `/monitor/websites` 及所有数据、创建、编辑、检查、暂停、排序、删除和 Nginx 导入入口都要求有效管理员 Session；数据响应设置 `Cache-Control: no-store`。
- HTTP/HTTPS 支持 GET、POST、状态码和返回内容判断、最多五次跳转、TLS 验证，以及保留 Host 与 TLS SNI 的本机直连地址。
- WebSocket 的连接成功、任意应用消息、匹配应用消息和 Ping/Pong 是四种明确成功条件；文本/二进制应用帧不得被当作 Ping/Pong 控制帧。
- Ping 载荷支持无载荷、UTF-8、Hex 和 Base64，解码后不得超过 125 字节；只有载荷逐字节一致的 Pong 控制帧成功。
- 首次失败进入复核，第二次连续失败才确认故障并打开事件；恢复、暂停、删除或重配会明确关闭事件或使旧结果失效。
- 活动监控最多 100 个，默认全局并发检查最多 10 个，同一监控不会并发检查；管理员顺序不随状态变化。
- Nginx 扫描与导入是两个动作；扫描只读且有文件数、单文件大小、总字节和 include 深度限制，不启动、修改或重载 Nginx。
- 24 小时原始结果、30 天小时聚合和一年故障/删除记录按保留期清理；页面空白时间段不伪造为成功。
- 桌面和移动页面可完成筛选、创建、编辑、立即检查、暂停/恢复、键盘移动与删除；增强脚本提供十秒刷新和拖拽排序。
- MVP 不发送邮件、短信、Webhook 或其他外部故障通知。
