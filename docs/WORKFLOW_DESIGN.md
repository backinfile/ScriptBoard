## 参数与发布契约

1. 一个输入至多一条数据线；输出可供多个输入使用。同类型可连接，json 输入可接收任意 JSON 类型。
2. 数据线和执行线共同决定拓扑顺序并检查环路。必填表示必须取得值，独立于是否必须连线。
3. 已连接的输入只取上游输出，缺失或类型错误立即失败；不使用本地值或默认值兜底。
4. Entry 保存工作流发布修订和实际配置。发布新版本后，旧 Entry 需编辑保存以显式同步，运行请求不允许临时覆盖参数。
5. 托管节点实例固定自定义定义 ID 与修订号。编辑定义不会替换旧实例；旧版本保留于服务端。
6. 每次运行固定发布定义、Entry 参数、引用变量和托管脚本。变量只在入队事务中解析一次；密码变量不能用普通取值节点读取。
7. 普通本地脚本仍以主机文件为来源，在执行时经主机文件边界检查并校验摘要；需要不可变脚本正文时使用托管节点。
8. 条件和按值分支仅激活命中出口；未命中路径标记 skipped。多个有效分支按依赖顺序执行，不支持循环、并发节点或任意步骤续跑。

## 架构与执行环境

- `internal/workflow`：字段/图校验、取值、版本仓储、资源锁、队列与引擎。
- `internal/web/workflow*.go`：会话权限、CSRF、JSON API、主机访问及 runmanager 适配。
- `workflow.js/css/html`：原生 JavaScript 页面，复用现有 SPA 导航，无新增前端构建链。
- `workflow-runner.py`：结构化 CLI 参数适配。通过现有一次性运行器监督进程树，JSON 结果与 stdout/stderr 分离。
- schema 71 添加工作流相关表，支持从 schema 70 及现有兼容版本升级，保留原数据。

本版执行位置为 ScriptBoard 所在主机。需要在该主机安装 Python 3，并按节点安装 Git、Go、Maven/JDK、Docker、kubectl、k3d、Node.js 或 Shell/PowerShell。可通过节点环境变量选择持久工具链与缓存。

Git 保留 URL 协议；Kubernetes 保留 kubeconfig/context/server 和显式跳过证书验证选择。Docker 使用指定 context/config 或主机默认配置，Registry 的 HTTP/TLS/证书策略由选定 daemon 控制；平台不会改写 daemon 或工作站当前 Kubernetes 上下文。跳过证书验证的风险在节点说明中可见。凭据使用主机已有配置文件引用。

## 失败与恢复

- 同一运行依赖顺序执行，不同运行仅在无互斥冲突时并发。
- 资源标签整组原子获取，相同资源按入队顺序等待。
- 非零退出、缺失/非法输出触发失败出口；未连接失败/完成处理时停止运行。默认只尝试一次，用户可显式配置重试。
- 排队取消与派发在事务中协调。运行中取消由现有监督器终止进程树，不进行业务回滚。
- 服务重启或进程监督状态不确定时转为 needs_attention，保留互斥资源。维护者核查后显式释放。
- 自定义节点与入口的编辑采用修订号比较；软锁阻止 Entry 编辑/删除，不阻止运行。

## 与业务项目的接入边界

需求文档中的源码同步、版本晋级、维护期发布、Schema、锁管理仍由各项目现有 run.py 承担。通过本地脚本节点配置绝对路径、参数数组、工作目录及互斥标签即可接入；平台不猜测 Java/Go 项目中不同的版本参数语义，不自动附加解锁、删数据或确认参数。

本次环境中需求文档所列业务项目路径未全部可用，因此没有操作业务仓库、正式 Registry 或真实业务集群。实际集成使用独立 QA 仓库、镜像、k3d 集群和 Maven 示例。分布式执行机、定时工作流、审批、通知、多分支并行不属于本版实现。

使用方式见 [工作流使用说明](WORKFLOW_USAGE.md)，验证证据见 [测试报告](WORKFLOW_IMPLEMENTATION_CHECKS.md)。

## 分层布局与页面整理（2026-09-10）

采用 ELK.js 0.12.0 layered，方向 RIGHT，按当前节点实际宽高与固定端口位置建模，同时纳入数据线和执行依赖。入口 FIRST、出口 LAST；算法保留模型顺序并固定随机种子。沿用现有贝塞尔连线，优化布局不承诺消除所有交叉。

官方 API 与 Worker 随应用分发，惰性加载；Worker 仅接收几何与拓扑，不发送节点脚本或配置。仅在草稿快照仍有效时一次性写入坐标并记录撤销。失败或超时保持原图。适应画布覆盖完整宽高和负坐标。坐标通过 CSSOM 更新以兼容严格 CSP。

页面采用项目共有的 primary-page-heading；单个主标题和内部页签，桌面画布与检查面板填满右侧剩余高度，窄屏纵向排列。冻结预览保持原样。

## 2026-09-10 控制路由扩展

控制边新增可选 outlet，旧边按 success 解释；拓扑排序按节点对去重，路由按出口判断。switch 的规则 ID 独立于名称和顺序，修改规则后连接保持稳定，删除规则移除对应连接。整数可以连接 number 输入，任何类型可连接 json。

引擎分别记录节点状态与激活出口，再解析有效路径的数据；失败处理不会隐式恢复运行。新增 workflow_step_runtime 附表保存尝试列表与触发出口，旧数据库启动时自动创建，原流程和历史兼容。失败重试只作用于已确认失败，监督不确定保留资源锁和人工核查流程。脚本正文仍由 ScriptBoard 管理。

节点类别新增 switch、merge、wait、terminate、arithmetic、compare、logic。详细操作见 WORKFLOW_USAGE.md。当前执行器保持顺序调度，不增加循环或并发调度。

## 2026-09-10 保存与等待交互精简

- 编排顶部只显示保存主操作，入口参数为次级操作，新建/删除进入更多菜单；画布工具按添加、撤销/重做、整理、缩放分组。参数/说明使用支持方向键的下划线页签。
- POST /workflow/save 在同一事务中校验并写入编辑定义与可运行版本；失败不覆盖已保存版本。旧 draft/publish 接口与版本记录保留用于兼容，页面不再暴露双状态。
- Entry.confirm 独立保存布尔值，旧记录缺省时继承原工作流设置；Entry 更多菜单增加页内打开对应工作流，保留未保存编辑保护。
- wait 保持定时等待兼容；新增 wait_for，通过控制边保存等待对象，默认全部完成，可选任一与成功/完成出口；沿用跳过与失败语义，禁止空目标和循环。
