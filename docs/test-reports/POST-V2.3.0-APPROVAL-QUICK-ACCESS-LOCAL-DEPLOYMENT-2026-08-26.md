# v2.3.0 后功能变更与本地部署测试报告

测试时间：2026-08-26（Asia/Shanghai）

测试分支：`codex/quick-run-inline-sort`

对比基线：`v2.3.0`

结论：**通过**。当前分支相对 `v2.3.0` 的功能变更已分类盘点；全仓 Go 白盒测试和仓库 Chromium 浏览器回归门禁通过，外部 Chrome Playwright/HTTP 黑盒验证 9/9 场景组通过，浏览器控制台错误为 0。隔离部署、State Root、测试数据、JSON 结果与截图均保留。

## 1. 自上个 Release 以来涉及的功能

以下范围为 `v2.3.0..72e3be3` 的已提交功能，加上本分支尚未合并的实现。

### 1.1 数据库工作区

1. MySQL 与 Redis 统一为同一套连接工作区、详情导航和页面结构。
2. MySQL/Redis 页签可在连接类型间混合展示，局部导航只替换所属工作区。
3. MySQL 新增查询工作台；只读查询与写模式分离，写模式通过近期认证确认。
4. 查询行数、超时等限制移入设置抽屉。
5. Redis 新增键浏览器，双冒号命名空间按层级分组。
6. 本地连接验证、安全连接、明文连接及显式跳过证书验证的行为得到加固。
7. 数据库详情面板、空状态、页签高度和抽屉层级完成统一与稳定化。

### 1.2 快捷执行

1. 快捷执行支持拖动排序，排序范围保持在各自分组内。
2. 页面只保留一个“调整顺序”按钮，并固定在“新建分组”左侧。
3. 点击后在当前页面原地进入拖动状态，不进行整页刷新；所有分组同时展开并可排序。
4. 支持取消恢复原顺序、完成后原地保存，以及聚焦卡片后使用方向键调整。
5. 删除了每个分组上重复的排序按钮。

### 1.3 外部接口与审批

1. 每个日志、上传、变量和快捷执行调用功能新增“需要审批”，默认关闭。
2. 新增“审批”页签，展示调用时间、Key、功能、动作类型、目标、输入摘要，以及上传文件名、大小和 SHA-256。
3. 开启审批后，调用返回 `202 pending_approval`；批准前不执行目标动作。
4. 上传在调用时写入私有缓存，批准时复核实际大小与 SHA-256 后再写入目标文件系统。
5. 批准通过原子领取保证只能执行一次；重复批准返回冲突。
6. 拒绝会删除上传缓存且不写入目标；配置变化、目标失效或执行失败进入失败状态。
7. 服务在审批执行中重启时，审批和调用记录统一恢复为 `failed/unknown`，处理中及孤立缓存被删除，避免不确定动作被重放。
8. 受管 Host Files 后端执行已批准日志时保留原配置的轮转大小与备份数量。
9. 未开启审批的外部上传直接通过受限 Host Files 批次边界写入目标。
10. 旧上传收件箱的包、模板、路由、授权规则、文件页入口和遗留暂存目录全部删除。

### 1.4 文件快捷访问

1. 文件行“…”菜单新增 Pin 操作；目录继续支持固定。
2. 固定文件时保存文件类型，点击后进入父目录并聚焦、滚动到该文件行。
3. 每个快捷访问条目的取消固定按钮左侧新增仅图标的编辑按钮。
4. 编辑按钮打开侧边抽屉，可修改独立显示名称，最长 128 个 Unicode 字符。
5. 条目支持鼠标拖动排序，也支持在拖动手柄上使用上下方向键排序；顺序实例级持久化。
6. 文件与目录共用最多 30 项的实例级列表；旧目录记录迁移后保持目录类型。

### 1.5 自定义页面、面板与界面清理

1. 新增可配置自定义页签，包含角色可见性、来源边界、加载时机与抽屉管理。
2. 自定义仪表盘可选择发布为顶层页签；既有面板默认不自动发布。
3. 修复自定义面板重复排序号、页签和抽屉层级问题。
4. 移除 AI Assistant 运行时、页面、Broker 能力、发布产物和残留自动化集成。
5. 统一主页面标题、导入/导出图标、操作菜单层级和部分运营控件。
6. 简化登录页文案，恢复文本预览对比度，稳定数据库与旧 Assistant 区域的纵向布局。
7. 外部日志文件列表的列宽、目标信息与操作区完成对齐。

## 2. 白盒测试条目

### 2.1 快捷执行

1. 单一顶层排序按钮存在且位于“新建分组”左侧。
2. 分组内不再渲染旧排序按钮或旧移动操作。
3. 无 JavaScript 回退模式可由 `?reorder=1` 进入排序状态。
4. 前端点击拦截默认导航并原地切换状态。
5. 所有分组展开、折叠按钮暂时禁用、卡片变为 draggable/focusable。
6. 拖动与键盘排序生成完整分组顺序并通过 CSRF 接口保存。
7. 取消恢复初始 DOM 顺序；保存成功后原地退出；失败恢复并报告错误。

### 2.2 审批领域与缓存

1. 新 Entry 的审批要求默认关闭，更新后可持久化开启状态。
2. 审批保存经过验证的调用输入、Entry 修订快照、来源、上传元数据和消息摘要。
3. `pending → processing` 为原子领取，同一审批只能领取一次。
4. 只允许 `approved/rejected/failed` 三种终态完成处理中的审批。
5. 启动恢复将处理中的审批及对应调用记录标记为未知失败。
6. 上传缓存限制 ID、最大字节数、私有目录和 0600 payload，并计算实际 SHA-256/大小。
7. 缓存只能领取一次；完成、拒绝、处理中断和孤立数据均清理。
8. 变量审批批准前值不变，批准后按变量类型再次解析并递增修订。
9. 日志审批批准前文件不存在，批准后写入；受管模式保留轮转配置。
10. 上传审批批准前目标不存在，批准后内容一致；拒绝时目标不变且缓存为空。
11. 快捷执行审批批准前无 Run，批准后只创建一个 Run。
12. 全局开关、Key、分组、Entry、审批开关、动作类型和 Entry 修订在批准时再次校验。
13. 批准与拒绝都校验会话权限和 CSRF，并写入审批、调用与审计状态。
14. 默认不审批的四类动作继续走即时执行路径。
15. 旧 `/resources/inbox` 路由及子路由返回 404。

### 2.3 文件快捷访问

1. 文件和目录 Pin 均通过 Host Filesystem 现存路径规范化。
2. JSON 返回 `path/label/href/kind`，文件链接包含父目录和 `focus_path`。
3. 自定义显示名校验非空与 128 字符上限。
4. 排序请求必须无重复且完整覆盖当前持久化列表。
5. 排序在刷新后保持，列表继续实例级全局共享。
6. 文件链接返回的文件页渲染唯一 `data-file-focus` 行。
7. schema 59 为旧固定项补 `target_kind=directory`，schema 20–58 均走显式兼容路径。
8. 文件菜单、编辑抽屉、拖动手柄与前端保存脚本契约均已覆盖。
