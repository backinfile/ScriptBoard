## 1. 产品定义

ScriptBoard 是一个自托管、单机、少量可信用户使用的主机文件与脚本操作台，为服务身份可访问的普通文件提供浏览和管理，并为其中的可信脚本提供本地执行、实时日志、历史追踪、快捷执行和内置计划。

它不是通用多用户运维平台，也不把管理员发布的脚本视为不可信代码。受管部署默认把 Run 视为最高权限宿主操作，由独立 Runner 以 root/LocalSystem 执行；管理员可通过 `runner_identity_mode: isolated` 改用受限 Runner 身份、网络与系统调用边界。无论 Runner 模式如何，文件访问与特权动作都由 Broker 的固定领域协议承担，不能从 Web 退回任意高权限进程启动。

## 2. 产品目标

管理员能够完成以下闭环：

```text
登录 → 浏览主机文件系统 → 选择脚本与参数 → 启动执行
     → 实时查看输出 → 停止执行 → 查询不可删除的历史
     → 保存快捷执行或计划 → 必要时从文件系统回收区恢复误删文件
```

MVP 保持 SQLite、单机文件系统与平台原生服务部署，不引入运行时集群依赖。一个 ScriptBoard 产品版本包含 Web、Privileged Broker、Runner 与 AI Host 四个内部组件；它们共享一个发布事务，但保持独立 OS 身份和 IPC 边界。

## 3. 信任与权限边界

- 实例使用固定四角色多用户模型，并且只允许一个系统管理员；脚本发布、执行和高风险操作仍受角色、step-up 与审计约束。
- 管理员发布的脚本视为可信业务代码，默认由独立 Runner 以 root/LocalSystem 执行；`runner_identity_mode: isolated` 可改为受限 Runner 身份和资源边界。
- Web 默认低权限：Windows 使用 LocalService + 独立服务 SID，Linux 使用无登录 `scriptboard-web`；只有固定 Broker 保留 LocalSystem/root。
- Runner 与 AI Host 都不由 Web 直接派生；AI Host 始终使用独立受限身份，Runner 默认使用 root/LocalSystem，显式 isolated 模式使用独立受限身份。Web 不能直接解封 Broker 秘密、读取 Host Files 或把任意命令交给高权限进程。
- 四组件必须来自同一发布版本；混合二进制/IPC 协议组合 fail closed。Web 与 Broker 常驻，Runner/AI Host 按需启动。
- 明文 HTTP 只能监听回环地址。非回环访问必须使用内置 TLS，或由同机可信 HTTPS 反向代理转发到回环后端。
- 所有文件、日志、SSE、变量和执行入口必须验证用户 Session 与声明式角色权限；匿名仅允许登录入口和无敏感内容的静态资源。

## 4. 信息架构

桌面端采用固定分组侧栏，移动端采用抽屉导航。导航按操作者意图组织：

```text
监控
  宿主概览
  应用
AI
  AI 助手
资源
  文件 | 变量 | 回收站
配置
  快捷执行 | 计划
历史
  运行记录 | 审计
设置
  账户 | 用户 | 显示 | AI | 应用更新
```

侧栏底部显示服务状态、当前运行数、语言选择和账户入口。新增、上传、运行、编辑与保存等聚焦任务使用可分享的语义化 GET 地址；桌面端支持 JavaScript 时在当前工作区右侧任务面板打开且不替换地址栏中的工作区 URL，不支持 JavaScript、移动端或直接访问任务地址时显示完整服务端页面。

主要路由：

- `/monitor`
- `/monitor/data`
- `/monitor/status`
- `/monitor/applications`
- `/monitor/applications/data`
- `/ai`
- `/ai/conversations/{id}`
- `/history/runs`
- `/history/runs/{id}`
- `/resources/files`（绝对路径通过 `path` 查询参数或表单字段传递）
- `/resources/variables`
- `/resources/trash`

- `/config/schedules`
- `/history/audit`
- `/settings/account`
- `/settings/ai`
- `/settings/updates`

根路径与已登录访问 `/login` 均重定向到 `/monitor`。本次信息架构是破坏性升级，不为旧 Web 路由提供重定向或兼容别名。

### 4.1 宿主概览

- 登录后默认进入概览；根路径和品牌入口均指向概览。
- 页面以“概览 / 详细数据”内部页签分层：概览快速展示宿主判断、CPU、内存、关键卷容量、磁盘与网络双向吞吐及最近五条活动 Run；详细数据展示 CPU 构成与 Load、Swap/Windows committed、逐磁盘 IOPS 与延迟、完整网络错误与丢包、ScriptBoard 服务进程和主机事实。
- 后台每 5 秒采样，最近 15 分钟保留实时样本；每分钟保存平均值和峰值并固定保留 24 小时。
- 支持 15 分钟、1 小时、6 小时和 24 小时时间范围，默认 1 小时。
- 单项采集失败或历史写入失败不得影响文件管理、计划或脚本执行；缺失、首个速率采样周期和平台不可用数据必须明确隐藏或展示占位，不得以零值或延续旧值代替。概览 HTML 首屏只读取当前快照，历史序列由 JavaScript 按需增强。
- 只有采集失败、数据超过 15 秒未更新和关键卷低于既有最低可写空间属于客观异常；不内置通用 CPU、内存告警阈值。

### 4.2 应用观测

- `/monitor/applications` 每 5 秒采集本机宿主应用和本机 Docker 容器应用的当前 CPU、内存、磁盘或块 I/O 及进程事实。
- 宿主进程按规范化可执行路径聚合；路径受限的进程可以显示，但不能 Pin。Docker 容器按本机 Engine 与规范化容器名标识，并明确显示容器名、镜像和 Docker 类型。
- 已 Pin 区与正在运行区拥有独立刷新开关：前者默认开启，后者默认关闭。已 Pin 折叠态只显示 CPU、内存和磁盘 I/O。
- 正在运行列表先搜索与类型筛选完整快照，再按任一可见列排序并返回前 100 项；桌面使用表头排序，移动端使用独立排序控件。
- Pin 与 Unpin 持久化到本机 SQLite，使用认证、CSRF 和 POST/Redirect/GET；无 JavaScript 时仍可搜索、筛选、排序和改变 Pin。
- 连续快照与指标不保存命令行参数；管理员明确展开运行详情时可以按需查看和复制实际命令，环境变量值默认不展示，实际命令不进入审计或服务日志。
- Docker Engine 不可用只降低 Docker 数据源能力，不阻断宿主应用观测或其他 ScriptBoard 功能。页面不结束进程、不控制容器、不生成通用资源告警。

## 5. 认证与会话

### 5.1 管理员初始化

- 首次启动自动创建用户名 `admin`。
- 自动生成至少 128 bit 随机熵的初始密码，写入权限受限的一次性文件。
- 首次登录强制修改密码；成功后删除一次性文件。
- Windows 托盘可复制初始密码。
- 启动时只可用用户名和绝对路径密码文件覆盖数据库凭据；YAML、环境变量和 CLI 的明文密码入口必须拒绝并给出迁移指引。覆盖值不同则重设账号并撤销全部 Session。
- 网页修改凭据时，如果启动配置仍提供覆盖值，必须提示下次重启会再次覆盖。

### 5.2 密码

- 只使用带版本化参数的 Argon2id，每个密码使用独立随机 Salt。
- 最少 12 个 Unicode 字符，最多 256 个 UTF-8 字节。
- 不强制字符类别组合，允许空格、中文和密码短语；不能与用户名相同。
- 修改密码要求当前密码；本机最高权限 CLI 可重设。
- 登录成功时可自动升级过旧的 Argon2id 参数。

### 5.3 Session

- 允许多个浏览器同时登录。
- 空闲 12 小时失效，绝对有效期 7 天。
- 浏览器只保存随机 Session ID，服务端只保存其哈希。
- 修改用户名或密码撤销全部 Session；普通退出只撤销当前 Session，并提供退出所有设备。
- 服务重启不使有效 Session 自动失效。
- Cookie 设置 HttpOnly、SameSite；HTTPS 模式强制 Secure。
- 所有状态修改请求必须使用 POST 等非 GET 方法并验证 CSRF Token。

### 5.4 登录限速

- 连续失败 5 次后开始指数退避，从 2 秒增加到最长 5 分钟。
- 同时按来源 IP 和唯一 admin 账号统计。
- 不永久锁定账号；本机 CLI 可清除限速状态。
- 登录成功、失败和限速均写审计事件，不记录密码。

### 5.5 双重认证与 step-up

- 账户可配置 RFC 6238 TOTP；已配置账户的密码登录和高风险 step-up 都必须提供动态验证码或一个未使用恢复码，不存在仅密码降级路径。
- 同一 TOTP 时间步只能接受一次。恢复码各自具有 128 bit 随机熵，只显示一次、仅保存摘要并在成功使用后原子移除。
- TOTP 状态整体由 State Root 外的统一主密钥密封；单独复制 State Root 不能恢复认证器 secret。
- 启用或网页重置 MFA 撤销该账户全部 Session；本机管理员重置同时清除管理员 MFA，作为丢失认证器和恢复码后的带外恢复路径。
- 账户可注册要求 authenticator user verification 的 WebAuthn/passkey；challenge 只在服务端短期保存并一次性消费，凭据记录由外部主密钥整体密封，登录与 step-up 成功后更新计数器与 flags。
- Administrator、Maintainer 默认带 MFA 注册截止时间。超过截止时间且未配置 TOTP 或 passkey 时，只允许进入账户/MFA/登出路径，其他状态改变请求在业务 Handler 前 fail closed 并审计；旧实例和首次部署使用有界注册窗口避免锁死唯一管理员。

## 6. 主机文件管理

### 6.1 顶层、路径与保护边界

- 文件页顶层显示“此主机”：Windows 列出可用本地、移动和网络卷，Linux 进入 `/`。
- 所有文件请求、快捷执行、计划和 Run 使用规范化绝对路径及平台比较键；Windows 比较不区分大小写。
- 最终访问由 ScriptBoard 服务身份的操作系统权限决定，不增加 impersonation 或逐目录授权。
- State Root、Install Root、活动配置、管理员密码文件、TLS 私钥和每个文件系统的 ScriptBoard 回收区为受保护路径：列表隐藏、直接访问拒绝。
- 受保护路径自身和后代不可访问；包含它的祖先不可编辑、移动、删除、覆盖或执行。
- 符号链接、Junction、Reparse Point 和特殊文件显示为受限条目但不跟随。Linux `/proc`、`/sys`、`/dev` 等内核虚拟文件系统只显示受限入口；真实磁盘、普通挂载、网络挂载和临时文件系统可以进入。

### 6.2 列表、搜索与快捷访问

- 每页 100 个条目，目录优先，支持名称、类型、大小和修改时间排序；搜索仅匹配当前目录。
- 隐藏文件默认不显示，Windows 同时识别 Hidden 和 System 属性；开关保留当前搜索和排序。
- 快捷访问在当前实例全局保存最多 30 个规范绝对目录路径，所有有文件页权限的用户共用且不依赖浏览器存储；旧浏览器固定项首次打开新版页面时一次性合并。失效、离线或受保护固定项不能进入，只能移除。
- Web 路由使用 `/resources/files?path=...` 等查询参数或表单绝对路径，不把盘符或根路径放入通配路由。

### 6.3 上传、创建、预览与编辑

- 支持多文件上传和新建目录，不支持目录上传、服务端解压、链接或特殊文件上传。
- 上传流式写入目标同目录临时文件；同名默认拒绝，明确确认后才通过回收区原子替换。
- 内置脚本/可执行扩展及 `executor_chains` 配置的扩展不能由普通上传直接进入主机路径：内容先以无扩展名、0600 权限进入 State Root 私有收件箱，管理员或维护员在近期认证后核对 SHA-256 和目标再发布。普通上传不能直接覆盖现有可执行文件；文件移动同样要求近期认证并单独审计。
- 在线编辑只接受不超过 1 MiB、有效 UTF-8 且不含 NUL 的普通文件，使用摘要冲突检测、同目录临时文件和原子替换。
- PNG、JPEG、GIF、WebP 可安全内嵌预览；主动内容和未知格式只下载。只下载单个普通文件，并设置 attachment 与 nosniff。
- 所有写操作按实际目标文件系统检查最低可用空间；运行中或被文件操作租约覆盖的路径拒绝修改。

### 6.4 移动、路径租约与引用

- 同文件系统移动使用原子重命名，并事务更新快捷执行和计划引用；历史 Run 保留启动时绝对路径。
- 跨文件系统移动先预扫描、检查空间与受限子项，再复制到目标同目录临时项，保留并验证内容与平台元数据，原子提交目标，将源移入源文件系统回收区，最后事务更新引用。
- 提交前失败或取消会清理临时项并保持源不变。服务重启依据持久化文件操作日志恢复或回滚；状态端点和 SSE 展示扫描、字节进度、提交与失败。
- 目录含链接或无法无损复制的特殊文件时在预检阶段拒绝。路径租约阻止 Run、移动、删除和恢复互相竞争。
- 绕过网页的外部移动不猜测文件身份，引用显示失效。

### 6.5 文件系统回收区

- 删除只移动到源文件系统中、带当前实例所有权标记的私有 ScriptBoard 回收区；无法安全建立时拒绝，不降级永久删除。
- 文件列表隐藏受保护的回收区，专用页面按原绝对路径恢复或显式永久清理；同名冲突默认保持两边不变。
- 删除被计划或快捷项引用的脚本前展示影响并确认；计划自动禁用，快捷项失效。恢复原路径后快捷项可恢复可用，计划不自动启用。

### 6.6 Linux 可执行位

- Linux 普通文件只提供所有者执行位 `u+x` / `u-x` 开关，不提供任意 chmod、chown、chgrp 或目录权限编辑；Windows 隐藏该功能。

## 7. 版本与兼容性边界

- 内置 Git 版本保护整体移除：没有设置页、检查点、恢复路由、数据库状态或 Git CLI 配置。
- 磁盘上的既有 `.git` 和历史不迁移、不修改、不删除，之后作为普通主机文件处理。
- 主机文件系统重构以 schema 20 为兼容基线；当前版本新建 schema 24，并允许 schema 20–23 在单事务内前向迁移。早于 20 或高于当前版本的 schema 都在写入前明确拒绝。
- `managed_root`、`git_executable`、对应环境变量、`--managed-root`、`--here` 等旧配置接口明确拒绝。
- 管理员必须使用新配置和新的 State Root；旧回收区、快捷执行、计划和浏览器固定项不迁移。

## 8. 脚本识别与执行器

### 8.1 无注册执行

- 受支持扩展名、位于允许主机路径的普通文件无需注册，直接在原位置执行。
- 不复制主机脚本快照；Run 保存启动时规范绝对路径与 SHA-256。
- 工作目录固定为脚本父目录。
- 脚本继承服务进程环境；额外注入 `SCRIPTBOARD_RUN_ID` 和 `SCRIPTBOARD_SCRIPT_PATH` 等非敏感元数据。

### 8.2 默认执行器链

Linux：

```text
.sh  → bash → sh
.py  → python3 → python
.ps1 → pwsh
```

Windows：

```text
.ps1 → pwsh.exe → powershell.exe
.py  → py.exe -3 → python.exe
.bat → cmd.exe
.cmd → cmd.exe
.sh  → bash.exe
```

- 候选可包含固定前缀参数，可按 PATH 查找或配置绝对路径。
- 只有执行器不存在或进程无法创建时才回退；脚本成功启动后，非零退出、超时或取消均不换执行器重跑。
- Windows Terminal 不是执行器；托盘不假定或提供一个全局脚本目录。
- WSL 不作为默认 `.sh` 执行器。

## 9. 参数与变量

- 参数输入采用跨平台简化 shellwords：空白分隔、单双引号和反斜杠转义。
- 不执行变量展开以外的环境展开、通配符、管道、重定向、`&&`、`;` 或命令替换。
- 不提供 Shell 模式。
- 变量名格式为 `[A-Z][A-Z0-9_]{0,63}`，最多 1,000 个。
- 变量均为普通明文值，最大 4 KiB；支持 `text`、`bool`、`integer`、`float` 和严格 `x.y.z` 的 `version` 格式类型，不提供范围、长度、正则或枚举约束。
- 变量可标记为密码类型以便在变量页面默认遮罩；该标记不提供加密或秘密存储。
- 引用格式为 `{{NAME}}`，必须独占一个参数，不能嵌入文本。
- 参数模板最大 16 KiB，最多解析为 256 个参数；解析后按实际执行器限制再次校验。
- 被快捷项或计划引用的变量不能删除；重命名时自动更新活动引用。
- Run 同时保存原始模板、模板参数数组和启动时解析后的实际参数数组。
- 大块输入通过允许的主机文件绝对路径传递，不存在“运行附件”概念。

## 10. 执行生命周期

### 10.1 并发与重叠

- 不设置全局并发上限，不建立队列。
- 手动或快捷执行同一脚本已有活动实例时，显示活动数量和启动时间并二次确认。
- 计划默认允许同一脚本重叠；计划项可选择禁止重叠，被跳过时记录计划触发事件而不创建 Run。
- 重叠和租约按规范化真实路径及操作系统文件 ID 判断。

### 10.2 执行租约

- 从启动请求被接受到该文件所有活动实例结束，禁止通过网页覆盖、编辑、移动、重命名或删除脚本。
- 脚本所有祖先目录禁止移动、重命名和删除，避免绕过租约。
- 同目录其他文件不锁定，系统也不承诺阻止绕过网页的磁盘修改。

### 10.3 超时

- 默认无超时。
- 手动执行可指定本次超时；快捷项保存来源 Run 超时；计划保存自身超时。
- 可配置允许的最大超时，默认 24 小时。
- 达到超时时先进入 `timing_out` 并请求优雅终止，默认等待 30 秒后自动强杀完整进程树。

### 10.4 手动停止

- 第一次点击停止：请求优雅终止，状态变为 `stopping`，按钮变为“强制停止”。
- 第二次点击：立即强杀完整进程树。
- 第一次手动停止后不按固定时间自动强杀。

### 10.5 服务生命周期

- 正常停服先停止接受新执行和计划触发，再优雅终止全部活动进程树；等待 30 秒后强杀残留，Run 记为 `cancelled`，原因是服务停止。
- Linux 使用独立进程组和父进程死亡信号；Windows 使用启用关闭即终止的 Job Object。
- 异常服务退出后，尽量由操作系统连带终止脚本；下次启动将原活动 Run 记为 `disconnected`。
- 浏览器刷新可通过 Run ID 与事件序号重新连接 SSE；服务重启后只允许读取已有日志，不重新接管进程。

## 11. Run 状态机

```text
starting → running → succeeded
                  → failed
                  → stopping → cancelled
                  → timing_out → timed_out
                  → disconnected
starting → failed
```

- 启动前校验失败不创建 Run；进程创建阶段失败创建 `failed` Run。
- 正常退出码 0 为 `succeeded`，非零为 `failed`。
- 停止或超时一旦触发，最终状态由该原因决定，不再被随后退出码改写。
- 不存在 `queued`。
- Run 元数据不可由管理员删除。

## 12. 日志与历史

### 12.1 执行日志

- 每个 Run 使用一份追加式事件日志，事件包含稳定序号、时间、stdout/stderr 来源和原始字节。
- 顺序表示 ScriptBoard 从两条管道读取到的顺序，不承诺进程内部精确时序。
- 页面不模拟终端：不分配 PTY、不接受 stdin、不执行 ANSI 控制序列。
- 保留换行、回车和 Tab，其他控制字符转义；无效 UTF-8 使用替换字符并标记。
- 每个 Run 默认最多 100 MiB：固定保留最初 5 MiB，并滚动保存最新约 95 MiB，中间插入截断事件。
- 即使日志被丢弃或写入失败，也持续排空 stdout/stderr，避免进程阻塞。

### 12.2 SSE 与页面容量

- SSE 使用事件序号与 `Last-Event-ID` 重连。
- 页面初始最多加载最近 5 MiB 或 5,000 条事件，取较小者。
- 浏览器最多保留 10,000 条事件，超出后只从 DOM 移除。
- 支持暂停显示、自动跟随与用户滚动后暂停跟随。

### 12.3 Docker 与主机文件源日志

- Docker 应用页可查看当前容器，以及仍可见的已 Pin 停止容器日志；日志直接来自本机 Docker Engine，不回退到其他数据源。
- 文件列表与文本预览可对允许路径中的普通文本文件启动 `tail -F`；读取继续遵守绝对路径规范化、受保护路径、普通文件与受限条目边界。
- 两类源共用全尺寸日志查看器：首次读取最后 500 行，向上滚动按最多 500 行或 1 MiB 分页，SSE 从不透明游标持续追加。
- 文件追加从原偏移继续；截断从文件头恢复；重命名轮转先排空旧句柄，再跟随同一路径新文件；删除期间等待，重建后恢复。旧源消失后不得把旧历史游标映射到新文件。
- Docker 非 TTY 日志保留 multiplex 顺序及 stdout/stderr 来源，TTY 标记为 combined；Docker 时间戳与正文分栏，正文不解析 ANSI。
- 每行最多 256 KiB，超长行拆为续片；无效 UTF-8 使用替换字符并标记，危险控制字符转义。
- 严重级别按完整解码文本不区分大小写地做任意位置匹配：`error`、`fatal`、`panic` 为 Error，`warn`、`warning` 为 Warning，同时命中时 Error 优先。stdout/stderr 不改变内容严重级别。
- 页面使用文本标识、左轨和柔和整行背景共同表达 Error/Warning；普通 stderr 只保留较弱来源差异，日志正文只通过 `textContent` 渲染。
- 暂停会关闭 SSE，继续时从最后游标恢复；清空只清理当前视图。浏览器最多保留 20,000 行或 16 MiB，并保留重新读取被淘汰历史所需的游标。
- 页面、JSON 和 SSE 都要求有效 Session 且使用 `Cache-Control: no-store`；最多同时 8 路 SSE 和 4 路历史读取，SSE 每 15 秒心跳，文件每 500 ms 检查增长或轮转。
- 源日志不写数据库、不落地副本，也不进入审计、执行日志或服务诊断日志；可读范围由原文件与 Docker 日志驱动的保留能力决定。

### 12.4 保留

- Run 元数据永久且不可手动删除。
- 日志默认保留 90 天，全局总量上限 1 GiB；先清理最旧已结束 Run 日志并标记 `log_expired`。
- 活动与 `disconnected` Run 不参与自动日志清理。
- 触发成功关系随 Run 永久保留；未创建 Run 的计划触发明细保留一年，之后按计划、日期和结果聚合为永久计数。

## 13. 快捷执行

- 维护员从主机脚本文件或历史 Run 主动保存具名快捷执行项，不自动为所有文件或历史生成入口。
- 保存脚本规范绝对路径及平台比较键、参数模板/数组、超时、可空来源 Run ID、名称、可空分组、组内排序和软锁状态；从文件保存只创建配置，不启动脚本。
- 管理员可编辑快捷项名称、参数和超时，但脚本路径与来源关系保持不变；也可复制为独立、默认未锁定的新快捷项，复制到原分组时紧随来源项。
- 管理员可创建、重命名、排序和删除分组，并在分组之间移动快捷项；每项至多属于一个分组，删除非空分组时条目按原顺序追加到“未分组”。
- 分组默认展开，可在浏览器内单独折叠；折叠偏好只保存在当前浏览器，不属于服务端配置。
- 软锁用于避免误编辑和误删除，服务端必须拒绝绕过界面的编辑与删除请求；锁定不阻止启动、复制、移动分组、排序或系统维护脚本引用。
- 默认单击即通过带 CSRF Token 的 POST 启动并跳转实时日志。
- 同脚本已有活动实例时改为二次确认；可将个别快捷项配置为始终确认。
- 文件失效时快捷项不可用；网页移动会更新路径；Run 来源删除不存在，因为 Run 不可删除。

## 14. 内置计划

- 不读取或修改系统 crontab。
- 计划保存在 SQLite，由服务进程内调度器执行，Windows/Linux 行为一致。
- 采用五段 cron（分钟、小时、日、月、星期），最小粒度一分钟；不支持秒或 `@every`。
- 页面提供可双向同步的常用规则与高级表达式，并预览未来五次触发时间。
- 所有计划使用实例统一时区，默认宿主时区，可用 IANA 名称覆盖；数据库时间戳保存 UTC。
- 不对夏令时跳变实现特殊补偿或去重。
- 服务停机期间不补执行；重启后只从下一次未来时间继续，并汇总记录错过次数。
- 计划分组是可创建、重命名、排序和删除的独立容器；计划只能选择已有分组或“未分组”，删除分组时计划保留并转为未分组。
- 计划保存名称、可空分组引用、脚本路径、参数模板、超时、启用状态和重叠策略。
- 指向被删除脚本的计划自动禁用且不会随恢复自动启用。

## 15. 审计

- 审计范围：登录、退出、文件变更、回收站、执行启动与停止、计划、变量、快捷项、账号/配置修改、Git 启停与恢复、日志清理等。
- 记录时间、操作、目标、结果和请求来源地址。
- 不记录密码、Cookie、CSRF Token、变量值、文件内容或请求正文。
- 默认保留一年，可下载，不允许网页逐条修改。
- 审计日志、Run 日志和服务诊断日志相互独立。

## 16. 服务、托盘与网络

### 16.1 CLI

```text
scriptboard serve
scriptboard service install [--start]|uninstall|start|stop|restart|status|verify
scriptboard admin reset
scriptboard config validate
scriptboard doctor
scriptboard version
```

- Windows 直接使用服务控制管理器，不依赖 NSSM。
- Linux 只正式支持 systemd。
- 正式发布包提供单一平台安装入口；它使用 `service install --start` 完成整体安装、自动验证和启动。显式 `service verify` 只作为高级诊断入口，不是正常安装后的必要人工步骤。
- `service uninstall` 不删除配置、主机文件、状态或已有 Git 历史。
- 不提供用户备份/恢复命令。

### 16.2 Windows 托盘

- 服务默认随系统启动；托盘默认随当前用户登录启动，并禁止重复实例。
- 无主窗口。菜单包含状态、打开网页、启动、停止、重启、查看服务日志、登录自启动和退出；不假定全局文件目录。
- 启停转换期间禁用重复操作；停止/重启有活动 Run 时显示数量并确认。
- 退出托盘不停止服务。
- 就绪状态同时检查 Windows 服务状态与 `/login` 可访问性；进程存在但 HTTP 未就绪显示“启动中”。

### 16.3 网络

- 默认 `http://127.0.0.1:8787`。
- 端口可配置；冲突时拒绝启动，不随机换端口。
- 非回环监听允许使用明文 HTTP，但部署文档必须突出其高权限暴露风险并推荐 TLS；不内置 ACME。
- 默认信任 `127.0.0.1/32` 同机 IPv4 反向代理；其他代理来源必须显式配置，才接受转发的客户端地址。
- 不提供公共 API、API Token、Basic Auth 或远程 CLI。

## 17. 配置、状态与诊断

### 17.1 配置优先级

```text
内置默认值 < YAML 配置文件 < SCRIPTBOARD_ 环境变量 < 命令行参数
```

- Linux 默认配置：`/etc/scriptboard/config.yaml`。
- Windows 默认配置：`%ProgramData%\ScriptBoard\config.yaml`。
- `--config` 可指定其他文件。
- 网页只读展示最终生效配置与非敏感来源，MVP 不在线修改启动配置。

### 17.2 SQLite

- 使用纯 Go SQLite 驱动。
- 启用 WAL、`synchronous=FULL`、foreign keys 和 busy timeout。
- 高频 Run 输出不逐事件写数据库。
- 数据库 schema 固定为 37；全新库直接创建 37，schema 20–36 只执行显式兼容迁移并在同一事务提交。早于 20 或高于当前版本的 schema 在任何写入前拒绝启动，不猜测迁移或删除旧状态。
- 检测到数据库完整性异常时拒绝提供执行能力，只允许本机诊断和人工恢复流程。

### 17.3 磁盘与日志

- 状态卷不足 100 MiB 时拒绝新执行。
- 任一实际目标文件系统不足 100 MiB 时拒绝在其中上传、保存、移动提交或建立回收区。
- 已运行脚本不因低磁盘自动终止；日志写入失败标记 `log_incomplete`。
- 服务诊断日志位于状态目录，单文件 10 MiB，保留 5 个；Linux 同时输出到 stderr/journald。
- 服务日志不得输出密码、Session、变量值、完整环境或请求正文。

### 17.4 doctor

`scriptboard doctor` 只读检查配置、受保护路径与权限、SQLite、Run/日志对应、执行器、端口、TLS、服务注册和关键磁盘空间。默认不修复，也不输出认证信息或变量值。

## 18. 网站监控

- 登录管理员可在独立“网站监控”页面维护最多 100 个 HTTP/HTTPS 或 WebSocket/WSS 端点；列表按管理员顺序展示并支持状态、服务位置筛选，不提供搜索。
- 保存或恢复后立即检查；首次失败进入复核，第二次连续失败才确认故障。默认全局最多并发检查 10 个，同一监控检查合并且不并发。
- HTTP 支持 GET/POST、200–399、任意成功返回，或以 `200;401-499;503` 形式组合指定状态码与范围；同时支持可选返回内容、最多五次跳转与 TLS 验证。管理员关闭 TLS 验证时只获得一小时、写入审计的临时例外，到期自动恢复验证。HTTP 请求与 WebSocket 握手均可配置最多 32 项自定义请求头；请求头值可嵌入 `{{VARIABLE_NAME}}` 并在每次检查时读取最新变量，配置只保存引用模板；协议栈管理的保留头不能覆盖。
- WebSocket 支持连接建立、任意应用消息、匹配应用消息和 RFC 6455 Ping/Pong 四类成功条件。应用文本/二进制帧与控制帧严格分离；Ping/Pong 只有收到载荷逐字节一致的 Pong 控制帧才成功，解码载荷上限为 125 字节。
- Nginx 扫描只能由管理员显式发起，先预览全部候选，再单独导入选中项；重复项不可选。扫描有文件数、单文件大小、总字节和 include 深度边界，不扫描端口、不修改或重载 Nginx。
- 页面每十秒渐进增强刷新；无 JavaScript 时仍可完成创建、编辑、筛选、立即检查、暂停/恢复、上下移动和删除。
- 原始检查结果保留 24 小时，小时聚合保留 30 天，完成故障与软删除配置保留一年。空白时间段表示没有检查，不伪造成功。
- MVP 不提供邮件、短信、Webhook 或聊天通知。

## 19. 技术与发布

- Go 单模块。
- 标准库 `net/http`、`html/template`、少量原生 JavaScript、SSE、纯 Go SQLite、`embed` 资源。
- 不引入 Node.js 构建链、SPA、Redis 或消息队列。
- Windows 托盘为同模块独立 GUI 可执行文件。
- 正式平台：Windows 10/11、Windows Server 2019+、systemd Linux；amd64 与 arm64。
- Windows 发布单文件 Setup EXE，Linux 发布单文件可执行 `.run`；两者都是原生启动器附加有界 ZIP 载荷，四个平台安装器均提供 SHA-256、载荷内 `RELEASE.json`，正式 Release 还提供 Ed25519 签名的发布清单。
- 正式 Release 以 Git Tag 作为版本事实来源。服务程序、托盘、托盘启动器和 updater 共用同一份构建元数据；开发构建必须明确标记为 `development`。
- 正式构建默认每 6 小时检查固定官方仓库 `backinfile/ScriptBoard` 的最新稳定版，只信任与内置公钥匹配的签名清单。检查失败不得影响已有服务能力。
- 单文件安装器从 updater protocol 2 起生效；protocol 1 安装必须手工执行一次新安装器建立基线，不能把不兼容资产伪装成可自动更新。
- 更新不会静默安装。管理员可在 Web 或 CLI 明确发起检查；下载验证与安装只在 Web 完成，并在安装前二次确认；第一版不提供无人值守定时安装。
- 新版 `service install` 将完整 Release 复制到版本化 Install Root：Windows 为 `C:\Program Files\ScriptBoard`，Linux 为 `/opt/scriptboard`。Linux 服务使用稳定的 `current` 入口，Windows 服务配置明确指向当前 Installed Release。
- 旧式“服务直接指向单个可执行文件”的安装不迁移、不兼容；发现同名旧服务或缺失新版安装元数据时必须拒绝安装，并要求管理员先手工卸载后全新安装。
- updater 必须独立于主服务进程运行。进入切换前先暂停调度和新 Run；只要存在活动 Run 就拒绝更新，不自动终止 Run。
- updater 在旧进程退出后创建一致数据库快照、切换服务目标并以 Validation Mode 启动新版本。验证期间不触发计划、不接受 Run 或业务写请求；服务状态、精确构建运行标记和 HTTP 就绪持续通过后才能提交。
- 验活、启动或数据库迁移失败时，updater 自动恢复旧服务目标和更新前数据库快照，并重新启动旧版本。已正常提交并产生新业务数据的版本不提供任意一键降级。
- 便携 Release 可检查版本和打开官方 Release 页面，但不允许原地自更新；源码开发构建既不自动检查也不下载更新。
- 每个平台只提供一个自解包安装器，不制作 MSI/DEB/RPM；安装器的 `--extract-to` 可恢复完整便携目录。
- Web 界面、状态、动作、错误和日期完整提供简体中文与美式英语；首次访问按 `Accept-Language` 协商，中文语言范围选择简体中文，其余选择美式英语，之后由 Cookie 记忆。URL 不带语言前缀；结构化标识和技术详情保持稳定英文。托盘和 CLI 帮助仍只提供简体中文。
- 自动化浏览器门禁固定为桌面 Chromium；Chrome、Edge、Firefox 和 Safari 为最佳努力兼容。移动端必须可完成核心操作，但不进入当前自动化截图门禁。
- 正式支持每台主机单实例；状态目录持有排他实例锁。

## 20. 非目标

- 多用户、角色、用户组、LDAP、OAuth、SSO
- 不可信代码沙箱或逐脚本身份切换
- 公共 API、API Token、远程 CLI
- DAG、流水线、多服务器、跨集群编排、通用 Kubernetes 资源编辑和集群生命周期管理；允许在监控页保存并切换多个独立集群连接
- Docker 作为正式部署方式
- 系统 crontab 集成
- Git 远程同步、子模块、LFS 和外部过滤器
- 用户备份/恢复命令
- 邮件、聊天通知和插件系统
- 交互式终端、PTY 和 stdin
- 文件夹上传、ZIP 打包下载和服务端解压
- 通用 chmod/chown 文件权限管理
- 无人值守自动安装、beta/nightly/自定义更新频道、更新镜像或任意仓库
- 旧式单文件服务安装迁移、旧资产命名兼容与旧 updater 协议兼容
- Web 之外界面的多语言和正式多实例支持

## 22. 一次性执行与快捷创建

- 快捷执行页提供“一次性执行”和“创建”两个入口；“创建”在允许的主机目录保存脚本和快捷项，
  但不启动 Run。
- 一次性源码创建在私有 `State Root/runs/{run-id}`，Run 使用单独选择并重新校验的
  普通主机 workdir；Run 永久记录源码摘要、语言/执行器、参数、超时和绝对 workdir。
- 一次性源码通过 Run 详情只读查看，不可编辑，也不能直接保存为快捷执行。
- 一次性源码跟随 `start_one_time_run` 审计条目回收；先删源码，失败保留审计重试；
  Run 记录和 Run 日志保留策略独立。
- 从源码创建快捷项遇到同名文件时必须显式改名、覆盖或取消；覆盖先把旧文件移入
  回收站，并展示现有快捷执行与计划引用影响。
- 详见 [一次性执行与快捷创建实施计划](./ONE-TIME-AND-QUICK-EXECUTION-PLAN.md)。

## 23. AI 助手与 Pi Runtime

- `/ai` 是所有已登录固定角色可访问的原生对话工作区；左侧对话 Rail、中部消息与
  Composer、右侧上下文 Inspector 共同组成桌面布局，移动端以分层布局保留核心操作。
- 每个对话由当前用户独占并必须选择一个已配置、带服务端 API Key 的 LLM；设置页可
  新增、修改、删除未引用配置并选择唯一默认模型。API Key 以 State Root 外部主密钥密封后只写入私有凭据
  文件，页面、SQLite、审计和普通日志均不回显。
- 新对话继承系统设置中的自动审批默认值；每个对话可在模型选择旁直接切换审批模式。
  该开关不改变固定角色权限；状态修改执行前仍重新授权并建立一次性审批记录。
- Composer 可引用经过当前角色实时校验的目录、文件、应用、网站、Run、快捷执行和
  计划。持久记录只保存稳定标识与安全标签；引用内容始终视为不可信数据。
- 每个对话同一时间只有一个 Agent Turn；消息先写数据库，再通过有界 SSE 流式更新。
  用户可以停止当前 Turn，断线可通过 Last-Event-ID 续传；服务重启把未完成内容标记为
  中断且不自动重放。
- Pi 只从 State Root 私有 Runtime 的绝对路径启动，并使用隔离的 home、session 和
  workspace。它不读取 PATH、全局 Pi、用户 Extensions/Skills/Prompts/Themes 或项目
  上下文，因此可与本机手工启动的 Pi 并存。
- 没有受信 Runtime 时保留历史和设置，但拒绝新 Prompt。正式 Runtime 固定携带
  ScriptBoard Extension，并通过进程绑定 Tool Broker 提供有界领域工具和覆盖网页动作的
  统一工具目录；不得以开放 Shell 或任意文件工具作为降级路径。
- 系统设置支持检查、在线安装、离线三件套上传、原子激活和回退签名 Runtime；离线
  安装仍校验 ScriptBoard 版本、系统平台、签名和归档摘要，并可使用 Pi 对单条 LLM
  配置执行不持久化正文的连接测试。
- AI 能力默认关闭，由系统设置显式启用。Provider 调用由部署者自行承担费用和数据
  合规责任；即使工具受限，Prompt 中引用的主机信息仍可能发送给所选外部 Provider。
