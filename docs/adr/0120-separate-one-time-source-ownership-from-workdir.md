# 将一次性源码所有权与工作目录分离

## 状态

Accepted

## 决策

一次性执行源码由 Run 持有，创建在 `State Root/runs/{run-id}/source.{ext}`，不会
进入受管文件、回收站或版本保护。Run Manager 使用调用方选择并重新校验的受管目录
作为 `exec.Cmd.Dir`，不从源码位置推导工作目录。

一次性 Run 永久保留源码摘要、文件名、workdir 和执行元数据；源码文件的保留期由
其 `start_one_time_run` 审计条目决定。删除审计条目时必须先成功删除源码；失败则
保留审计条目重试。Run 日志保留策略与源码生命周期独立。

从源码创建快捷执行是另一条持久化流程：脚本属于受管目录，快捷执行项只引用脚本。
覆盖冲突把旧文件移入回收站，数据库写入失败时恢复文件系统。

## 原因

把一次性源码放在 workdir 会让临时实现泄漏进持久文件管理，也会让源码清理与
用户文件生命周期混淆。把 workdir 固定为私有 Run 目录又会破坏脚本对相对路径的
预期。分离两者可同时保留精确执行快照和明确的工作目录语义。

审计条目是一次性高权限执行的治理记录。让源码随该记录回收，使源码可追溯窗口与
治理窗口一致，而不会让 90 天 Run 日志清理提前删除源码证据。

## 后果

- `$PSScriptRoot`/脚本自身目录指向私有 Run 目录，相对路径仍从所选 workdir 解析。
- 一次性源码不能直接变成快捷执行；持久化必须走“创建”流程。
- 审计清理需要协调文件系统与 SQLite，并以“先删源码、失败保留审计”方式重试。
- Run 历史能在源码回收后继续展示元数据和结果，但源码入口返回 HTTP 410。
