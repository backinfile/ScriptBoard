# 按需流式读取 Docker 与主机文件日志

ScriptBoard 使用统一、源无关的日志接口直接读取本机 Docker Engine 和任意允许访问的主机普通文本文件，不保存源日志副本，也不写入 SQLite、审计、执行日志或服务诊断日志。历史读取以最多 500 行或 1 MiB 的正序页返回，实时追加使用 SSE；版本化 Base64URL 游标绑定容器或文件身份与读取边界，无法证明连续时必须显式报告缺口，不能把旧源游标静默映射到替换后的新源。

文件源以纯 Go 实现 `tail -F`：轮转时排空旧句柄、截断后从头继续、路径删除时等待重建，并在每次打开或重建时复用主机文件模块的绝对路径、受保护路径、链接与挂载边界。Docker 源保留 multiplex 顺序、stdout/stderr 或 TTY combined 来源与 Docker 时间戳；Engine、容器或日志驱动不可用时不回退到其他数据源。

历史与实时内容经过同一安全解码和严重级别判定：单行最多 256 KiB，超长行拆为续片，无效 UTF-8 与控制字符显式处理；`error/fatal/panic` 优先于 `warn/warning`。浏览器只保留 20,000 行或 16 MiB，服务端限制 8 路 SSE 与 4 路历史读取。所有入口要求 Session、禁止缓存，正文只通过 `textContent` 渲染。该边界用按需 I/O 和有界临时内存换取无需日志摄取、索引、迁移与保留策略的单机实现。
