# 使用实例级固定用户角色

## 状态

Accepted

## 决策

ScriptBoard 使用四种固定且互斥的实例级角色：`administrator`、`maintainer`、
`operator` 和 `viewer`。系统管理员唯一、始终启用且不能降级；只有系统管理员可以
创建和管理用户。维护员拥有除用户管理外的全部能力。执行员可以读取受管文件、执行
受管脚本与全部快捷执行项，并且只能停止自己启动的 Run。观察员只能查看约定的运营
页面与原始 Run 日志，不能访问文件页或发起操作。

角色权限在路由入口统一判定，覆盖 HTML、JSON、下载、POST、SSE 和任务表单。页面
同时隐藏无权导航与动作，但隐藏不是安全边界，直接请求仍返回 HTTP 403。快捷执行
分组和计划分组只用于页面组织，不参与授权。

用户由系统管理员手动创建，创建和重置密码时生成随机密码并只在成功响应中展示一次。
密码重置、角色变更和停用递增授权版本、撤销该用户全部 Session，并取消仍在运行的
认证请求与流式连接。账号不永久删除，以保留 Run 和审计归属。

Run 保存启动用户稳定 ID 与用户名快照；系统计划触发没有普通用户所有者。审计事件
保存操作者稳定 ID、用户名和角色快照，但禁止记录密码、Cookie、CSRF Token、变量值、
请求正文和文件内容。

## 原因

实例面向少量可信运维用户，不需要项目、用户组或可组合权限。固定角色能让授权矩阵
保持可测试、可解释，并避免分组同时承担页面组织和安全边界。稳定用户 ID 与快照让
用户改名、停用或长期保留历史后，Run 与审计仍能解释当时归属。

## 兼容性

该决定引入新的用户、Session、Run 和审计 Schema，不迁移旧 `admin` 表或旧业务数据。
检测到较旧 State Root 时启动必须明确失败，不得覆盖、删除或自动升级；部署者需要
使用新的 State Root。受管根目录仍是独立的全局目录，可以由新实例继续使用。

## 后果

- 不提供项目、自定义角色、权限开关、用户组、分组授权、SSO、LDAP 或 OAuth。
- 普通用户只能在验证当前密码后修改自己的密码；用户名、角色和状态由系统管理员管理。
- 管理员和维护员可以查看密码类型变量；执行员和观察员不能访问变量页。
- 所有可查看 Run 历史的角色都能查看原始 Run 日志，并接受脚本输出可能包含秘密的风险。
- 登录限流同时按来源 IP 和目标用户名计数；Session 继续使用 12 小时空闲期限与
  7 天绝对期限。
