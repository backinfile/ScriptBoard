# 代理 Assistant 工具并将状态修改绑定到一次性审批

Pi 不直接获得 Shell、文件写入、数据库或 ScriptBoard 内部 HTTP 权限。所有 AI 工具必须由 ScriptBoard 固定发布的 Extension 经版本化本地 Tool Broker 调用，并复用现有领域模块；Web handler、Extension 和 RPC Adapter 不复制路径保护、角色授权或业务约束。

Tool Broker 为每个受管 Pi 进程发放随机、短期、进程绑定的 capability，并在每次调用时重新校验对话所有者、用户启用状态、固定角色、授权版本、参数上限和目标当前状态。只读结果必须有字节、条目和时间窗口上限，标记截断与来源，并把文件、日志、网站响应等外部内容视为不可信数据。工具正文、凭据、绝对私有路径和完整环境不得进入审计或普通诊断日志。

任何修改 ScriptBoard 状态的工具调用都必须建立参数摘要、目标状态、用户授权快照和过期时间绑定的一次性 Action Approval。手动模式在对话中展示内联批准/拒绝；自动审批模式只代表由对话所有者自动作出同一份有界批准，不能绕过角色权限、执行时重新授权、领域冲突或审计。参数、目标、用户角色、授权版本或对话归属发生变化时，已有批准立即失效；服务重启不得重放结果未知的修改。

在固定 Extension 与 Broker 尚未随受信 Runtime 发布时，生产启动必须使用无工具模式。这个安全默认优先于提供不完整的运维能力。
