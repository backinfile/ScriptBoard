# 为账户增加无降级旁路的 TOTP 与单次恢复码

账户可以在近期认证后的浏览器会话中配置 RFC 6238 TOTP。认证器 secret、最后接受的时间步与
恢复码摘要映射整体保存在 `state-root/secrets/account-mfa.enc`，由 ADR-0143 的 State Root
外部主密钥以独立用途绑定 AES-256-GCM 密封。TOTP 接受当前时间步前后各一个步长以容纳时钟
偏差，但已接受及更早的时间步一律拒绝重放。

启用 MFA 后，密码登录和高风险 step-up 都必须再提供 TOTP 或一个未使用恢复码，不提供第二
因素时不创建低保证会话。成功登录记录 `aal2`，成功 step-up 记录 `aal2+step-up`。恢复码各自
具有 128 bit 随机熵，只在确认页显示一次，持久状态仅含 SHA-256 摘要；匹配使用常量时间比较，
成功后在同一次原子文件替换中移除。配置成功、网页重置和本机管理员重置都会撤销账户会话；
本机重置同时清除管理员 MFA，作为认证器与恢复码全部遗失时的带外恢复路径。

登录表单始终显示可选的第二因素字段，失败消息不区分用户名、密码或 MFA，避免由响应形成新的
账户/MFA 枚举面。WebAuthn/passkey 和 Administrator/Maintainer 的默认强制注册策略仍是独立
后续工作；在它们完成前，本决定只声明“已配置 MFA 不存在密码降级旁路”，不声明 P0-07 整体
完成。
