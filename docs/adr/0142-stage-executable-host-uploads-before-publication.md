# Host Files 可执行上传先进入私有收件箱再发布

Host Files 的普通文档上传继续使用目标同目录临时文件和原子替换，但可执行内容不再由同一
请求直接进入主机路径。内置脚本、原生可执行格式及 `executor_chains` 声明的扩展先写入
State Root 私有上传收件箱：随机目录、固定无扩展名 payload、0600 权限，并保存目标、大小
和 SHA-256 metadata。接收成功只表示等待复核，不表示目标文件已经存在。

管理员或维护员必须打开收件箱，在近期密码认证窗口内提交完整 SHA-256 和明确确认。发布
过程并发领取 payload、重新读取全文件校验大小与摘要、密封发布意图，再通过 Host Files
原子上传边界写入目标。成功后删除私有副本并记录包含 inbox ID、摘要与最终目标的审计；
失败可安全释放或按发布意图恢复。普通上传不能直接覆盖已有可执行文件，避免单次请求替换
正在使用或已受信的脚本。

将普通文件改名或移动为可执行扩展仍是独立文件状态变更，因此 POST move 也要求近期认证
并保留原有文件操作审计。这个边界不声称脚本内容安全；发布后的管理员脚本仍属于受信代码，
但从不可信字节到可执行路径至少需要第二个明确、可关联和可撤销前的人工动作。
