# 使用版本化服务安装与外置更新程序

新版单文件安装器先安全提取内嵌的完整正式 Release，再由 `service install` 复制到版本化 Install Root 并保存可验证的安装元数据。Linux 服务通过原子 `current` 符号链接引用当前版本；Windows 服务配置直接指向当前版本目录。缺少安装元数据、载荷不完整或发现同名旧式服务时拒绝安装，不猜测、不迁移也不删除旧目录。

更新由独立于 ScriptBoard 主服务进程的 updater 执行。主进程完成下载、签名与归档验证、暂存目标 Installed Release 并持久化 Update Operation 后，把控制权交给 updater 并正常退出。updater 等待旧进程停止，在此之后保存一致数据库快照，切换服务目标并启动新版本。

目标版本先进入 Validation Mode：计划暂停，Run 和业务写请求被拒绝。只有服务状态、精确构建运行标记和 HTTP 就绪持续通过后才提交；启动、迁移或验活失败时，updater 停止目标版本，恢复旧版本与更新前数据库快照，并重启旧服务。更新事务的阶段与结果保存在 State Root，数据库回滚不能抹去恢复事实。已经提交并产生新业务数据的版本不提供任意一键降级。

此决策扩展 ADR-0075 的向前迁移安全模型和 ADR-0100 的内部快照边界，并取代 ADR-0077 中关于归档内容与服务目标路径的细节；当前使用自解包安装器而不引入 MSI、DEB、RPM、安装向导或通用用户备份功能，便携场景通过安装器的显式解包模式提供。
