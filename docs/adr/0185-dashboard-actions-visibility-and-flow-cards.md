# ADR 0185: Dashboard actions, four-tier visibility, and flow cards

自定义面板的操作按钮不建新表，直接存进卡片 `config_json` 的 `actions` 数组。操作与卡片同生命周期、同导入导出，单独建表只会引入外键与级联一致性负担而没有独立查询需求。`browser_http` 操作只允许声明访客凭据的请求头名，字段集合以 `DisallowUnknownFields` 收口，静态秘密值在结构上没有存放位置；服务端触发的 `quick_run` 操作沿用 ADR-0127 的有界外部触发结论，按操作 ID 解析快捷执行项，`quickRunId` 永不下发到公开页面。

面板可见性由布尔 `is_public` 改为四档：私有、公开只读、公开可操作（访问 Key 保护）、匿名可操作。匿名可操作档不新增任何服务端端点，只下发 `browser_http` 操作，请求由访客浏览器直发目标地址，实例不代理、不持有凭据；公开可操作档的服务端触发端点按 slug + 卡片 + 操作逐层校验，任一不满足统一 404 防枚举。访问 Key 为 32 字节随机值，以 State Root 外主密钥密封落库，明文仅在生成时展示一次，连续失败锁定沿用内存计数、重启清零。

流程卡片第三次以重建 `custom_dashboard_cards` 的方式扩展卡片类型 CHECK（新增 `flow`），而不是放宽约束或改用 `ANY` 类型列：类型枚举保持在数据库层可校验，历史重建脚本已证明该路径可迁移。流程定义以规范化 JSON 存 `config_json` 的 `flow` 键（`run` 名称已解析为 `runId`），YAML 只是编辑抽屉的输入草案，保存时解析校验后丢弃，渲染与执行不重复解析 YAML。节点 ID 限制为安全字符集以直接用作 DOM/SSE 标识，DAG 结构、数量上限与 runId 存在性在所有写入路径（含导入）统一校验。

post 步骤的 `when` 语义为 `on_success`（全部节点成功）、`on_failure`（任一节点失败）与 `always`（默认），只表达节点终态，不携带节点输出值；需要分支逻辑时拆成多张流程卡片而不是在 post 中引入表达式。导入导出沿用 ADR-0139 的文件边界校验与 ADR-0132 的脱敏边界，快捷执行项引用按名称重映射（网站监控 monitorId 同一先例）：操作未匹配降级丢弃，流程节点未匹配拒绝导入，因为 DAG 不允许缺节点。

节点与全局均支持 post。内置 uses 作为带摘要的 `.sbflow` 固定操作描述经过已认证 Runner IPC，由 Runner 身份执行；Web 不启动 git、不执行主机文件操作。文件内置仅允许卡片工作区内相对路径；任意主机路径操作继续通过管理员发布的脚本。内置 HTTP 是显式受信自动化能力，允许 HTTP/HTTPS 与内网，跳过证书验证必须显式设置。此能力与展示卡片的出站抓取策略分开。

流程历史的快照与原子文件替换串行化；启动时返回深拷贝状态，并在关闭时拒绝新任务。公开状态接口重复校验面板、操作和当前 Key，仅返回该 Key 触发任务的状态，不返回路径或日志。
