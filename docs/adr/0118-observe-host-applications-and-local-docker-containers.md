# 观测宿主应用与本机 Docker 容器

ScriptBoard 在认证后的“监控”组中提供独立应用观测页面，每 5 秒只读采集宿主进程与本机 Docker Engine。宿主进程按规范化可执行路径聚合；容器按本机 Engine 与规范化容器名标识。CPU 按整机归一，内存与 I/O 使用各数据源的客观计数。路径不可读的进程可以显示但不能 Pin，PID 复用和计数器回退不能跨进程派生速率。

Docker 接入使用官方 `github.com/moby/moby/client`，只接受默认本机 Unix socket 或 named pipe，自动协商 API，并以短超时和有界并发读取运行容器的单次 stats。Docker 不可用是局部能力缺失，不影响宿主进程、脚本执行或宿主概览；Linux 上已识别的容器 cgroup 进程不再重复聚合为宿主应用。

管理员可以将任意数量的宿主应用或容器 Pin 到本机 SQLite。Pin 只改变观察优先级，不改变进程或容器。页面与 JSON 数据路由都要求有效 Session；Pin 状态变化要求 CSRF 保护并遵循 POST/Redirect/GET，审计只记录不透明应用 ID，不记录可执行路径或镜像。

连续采样、当前快照、分钟指标和审计不采集或保存命令行参数。管理员明确展开运行详情时，认证页面可以按需读取、展示并复制实际命令；该值不得写入指标、审计或服务日志。环境变量值默认不展示。此处以按需访问和清晰边界接受实际命令可能包含敏感参数的风险，并取代原计划完全不展示命令行参数的决定。

页面以当前状态为第一层：已 Pin 与正在运行列表拥有独立刷新开关，前者默认开启、后者默认关闭；桌面所有可见列可排序，移动端使用独立排序控件。已 Pin 折叠态只显示 CPU、内存和磁盘 I/O。功能保持只读，不结束进程、不停止或重启容器、不提供阈值告警、通知、导出、远程 Docker context、容器编排或公共 API。

此决策保留 ADR-0107 的有界宿主概览，并取代其中把 Top 进程整体排除在产品之外的部分；应用观测是独立页面和模块，不能改变宿主概览的客观异常判断。
