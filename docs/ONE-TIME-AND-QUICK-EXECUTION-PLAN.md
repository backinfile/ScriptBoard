# 一次性执行与快捷创建实施计划

状态：Implemented

## 目标

快捷执行页提供两个独立入口：

- **一次性执行**：接收源码并立即创建 Run。
- **创建**：先在受管目录创建脚本，再创建快捷执行项；不立即执行。

两条流程共享语言、源码、参数模板、超时和受管工作目录的校验，但具有不同的
所有权与生命周期。

## 一次性执行

表单包含受管工作目录、显式语言、UTF-8 源码、参数模板和可选超时。平台展示固定
语言集合：Windows 为 PowerShell、Batch、Python；Linux 为 Shell、Python、
PowerShell。提交时才检查实际执行器，缺少执行器时不得创建源码或 Run。

Run Manager 在所有无副作用校验通过后生成 Run ID，并以独占方式创建：

```text
State Root/
  runs/
    {run-id}/
      source.{ext}   # 私有、应用内不可修改、源码快照
      events.jsonl   # 独立日志生命周期
```

源码最大 1 MiB，必须是无 NUL 的有效 UTF-8。写入、同步并关闭后将权限降为只读。
脚本路径与所选工作目录分离：执行器读取私有源码文件，`exec.Cmd.Dir` 使用
`Managed Root/{workdir}`。因此 `$PSScriptRoot` 指向私有 Run 目录，而相对文件访问
从所选 workdir 开始。

Run 永久记录源码 SHA-256、语言对应的实际执行器、参数模板与解析后参数、超时、
运行身份、workdir、源码文件名、状态与结果。Run 详情提供只读源码入口，但不能将
一次性 Run 直接保存为快捷执行项。

`start_one_time_run` 审计条目与 Run 在同一数据库事务中建立关联。一次性源码的
回收严格跟随该审计条目的删除：默认一年保留期到期时先删除源码，再把 Run 标记为
`source_expired` 并删除审计条目；源码删除失败时保留审计条目，下次启动继续重试。
源码回收后访问返回 HTTP 410，Run 元数据、摘要、结果和独立的 Run 日志生命周期
不受影响。

## 创建快捷执行

表单包含受管工作目录、语言、文件名 stem、源码、快捷执行名称、分组、参数模板与
可选超时。系统追加平台语言扩展名；快捷执行名称默认跟随文件名 stem；分组默认
“未分组”。

提交顺序：

1. 校验 CSRF、语言、执行器、workdir、源码、文件名、参数、超时与分组。
2. 在所选受管目录原子写入脚本。
3. 在同一业务事务中创建快捷执行记录。
4. 返回快捷执行列表，不启动 Run。

同名目标先返回 HTTP 409 任务面板，显示现有快捷执行/计划引用数量并要求选择：

- 覆盖：活动 Run 使用的目标或非普通文件不可覆盖；旧文件先进入回收站。
- 改名：提供可编辑的可用名称建议。
- 取消：不产生任何变更。

若快捷执行记录或回收站记录写入失败，移除新文件并恢复被替换文件。以后删除快捷
执行项只删除入口，不删除其受管脚本。

## 受管目录与安全边界

目录选择器只通过受认证的 `/resources/directories` 逐级列出可进入的普通受管
目录。最终提交仍由 `managedfiles.Store.PrepareDirectory` 重新校验相对路径、
符号链接和挂载边界，不能信任浏览器提交值。

本功能沿用 ScriptBoard 的可信脚本安全模型，不是沙箱；脚本继承服务运行身份，
可以访问该身份本来能够访问的资源。功能不提供 stdin、PTY、交互终端、语言自动
识别或直接创建计划。

## 数据库与兼容性

数据库 schema 17 为 `runs` 增加：

- `script_kind`
- `working_directory`
- `source_filename`
- `source_expired`
- `source_audit_event_id`

旧 Run 迁移后默认为 `managed`，现有启动、日志、快捷执行和计划行为保持不变。

## 验收

- 页面同时提供“一次性执行”和“创建”，并支持完整无 JavaScript 提交。
- 一次性源码只存在于私有 Run 目录，实际 workdir 为所选受管目录。
- Run 详情可查看源码快照和 workdir，源码摘要与实际字节一致。
- 创建流程写入受管脚本和快捷项但不执行；冲突必须显式选择且覆盖进入回收站。
- 审计过期先回收源码；失败保留审计；日志清理不删除源码。
- Windows 与 Linux 的平台语言、执行器失败、路径边界、1 MiB、UTF-8、NUL、参数
  与超时边界均有服务端约束。
