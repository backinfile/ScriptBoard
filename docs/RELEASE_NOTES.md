# ScriptBoard v2.0.22

## 旧数据迁移

本版本使用数据库 schema 48，并可在首次启动时通过单个事务自动迁移 schema 20–47。`v2.0.21` 使用 schema 35，属于可自动迁移范围；迁移会保留原有用户、脚本引用、快捷执行、计划、运行记录、审计记录、监控配置和 AI 数据。

`v2.0.21` 及更早版本使用 updater protocol 1，不能识别本版本的单文件安装器，因此第一次升级必须手工完成：

1. 记录当前 `config.yaml` 和 `state_root` 的绝对路径，停止所有 ScriptBoard 服务，并备份这两个位置；不要只备份安装目录。
2. 使用旧版本二进制执行 `scriptboard service uninstall`，移除旧式服务定义。此操作不删除 State Root。
3. 从本 Release 下载与系统和架构匹配的 `*-setup.exe` 或 `.run` 单文件安装器，以管理员/root 权限运行；使用自定义配置的实例必须继续传入原来的 `--config CONFIG_PATH`。
4. 新服务首次启动时会原子迁移原 State Root 中的数据库。登录后确认用户、快捷执行、计划、运行历史、外部接口、自定义看板和 Kubernetes 连接均存在，再恢复业务运行。

如果数据库 schema 低于 20，或配置仍包含已移除的旧字段，请不要直接启动新版本。请保留原数据副本，创建新的配置和 State Root，再按业务对象人工迁移。数据库一旦由新版本成功提交，禁止再用旧版本二进制打开；需要回退时应停止全部服务并恢复升级前备份。

完成这次 protocol 2 基线安装后，后续版本可继续在“系统设置 → 更新”中下载、验证和事务更新。
